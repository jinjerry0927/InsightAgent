# Phase 6 로컬 대시보드

기준일: 2026-10-30. Phase 5 최종 재검토 후 Streamlit 화면을 연결했다. 구현·테스트·실제 브라우저 검증 완료, 사용자 최종 검토 대기다. Phase 7은 착수하지 않았다.

## 시작과 사용

현재 PC에는 DB·API 설정·패키지 설치가 완료되어 있다. 서버가 실행 중이면 [로컬 대시보드](http://127.0.0.1:8501)를 연다. 서버가 꺼져 있을 때 프로젝트 폴더에서 실행한다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m streamlit run app.py
```

직접 실행한 터미널에서는 Ctrl+C로 종료한다. 127.0.0.1에만 연결하는 로컬 단일 사용자 화면이며 배포·로그인·공유 서버는 구현하지 않았다.

1. **기준 분석**에서 4개 지표 중 하나를 고른다. 모델 없이 검토된 SQL로 실제 로컬 DB를 조회한다.
2. **AI 질문**에서는 질문과 기간을 입력한다. 기본은 모델 최대 1회·SQL 수정 0회·후보 조회 1회다. “응답 수정 1회 허용”을 선택하면 모델 최대 2회·수정 1회·조회 2회로 늘어난다. 인증·한도·위험 SQL·자원 오류는 수정하지 않는다.
3. **분석 실행**을 눌러 요청한다. 질문·기간 입력, 모드 변경, 탭·차트 조작·화면 재실행만으로 API를 호출하지 않는다. 버튼을 다시 누르면 새로운 분석 요청이다.
4. 결과의 **차트 / 집계 표 / SQL·계산 기준 / 실행 정보**를 확인한다. 마지막 실행의 방식·질문·기간을 결과 위에 표시해 현재 입력과 이전 결과를 구분한다.

마지막 날짜는 화면에서 **포함**한다. 서비스가 하루 뒤 날짜를 배타적 종료 값으로 바꿔 기존 `[start, end)` SQL에 바인딩한다. 예를 들어 2017-01-01~2017-01-31은 1월 31일 23:59:59 주문까지 포함한다. 원본 시간대는 임의 변환하지 않는다.

## 화면과 근거

| 화면 | 의미·확인할 점 |
| --- | --- |
| 데이터 범위 | 로컬 DB의 실제 구매일 범위·전체 관측 주문·배송 완료 주문. 분석 기간의 결과와 구분 |
| 매출·주문 카드 | 배송 완료 상품금액·배송비 제외·구매 월 기준. Decimal의 정확한 금액을 문자열로 표시 |
| 카테고리 TOP 5 | 표시한 카테고리만의 합계이며 전체 매출 아님. 같은 번역명도 원문 코드로 구분 |
| 배송 지연율 | 월별 비율의 평균 대신 기간 전체 지연 주문 / 비교 가능 주문. 분모 0은 미확인 |
| 리뷰 평점 | 그룹별 유효 표본과 평균. 전체 스냅샷의 최신 리뷰이며 기간 끝 당시 의견·인과관계로 해석하지 않음 |
| 차트 | 코드가 허용한 Plotly 선/막대만 사용. 미관측 월·NULL은 gap/결측으로 유지하고 0으로 채우지 않음 |
| 집계 표 | 실제 SQL의 품질 건수·소계·완전한 합계를 함께 표시. `—`는 결측 |
| SQL·계산 기준 | 실행 후보·바인딩 정책·KPI 한계·관측 범위. SQL 편집·직접 실행 기능은 없음 |
| 실행 정보 | 실제 API 시도·입력/출력/총 토큰·모델/조회 시간·SQL 수정/조회 횟수·상태 전이 |

그래프 위치에는 시각화용 float를 사용하지만 금액 카드·표·hover는 정확한 Decimal 표시를 유지한다. NULL 금액이 있으면 전체 합계를 0이나 소계로 대체하지 않는다. 행 상한에 도달하면 부분 표·그래프임을 알리고 전체 기간 합계 카드는 표시하지 않는다.

## 구성과 의존성

- `app.py`: Streamlit form·세션의 마지막 결과·상태별 표시. 모델 호출 코드는 명시적 제출 분기에만 있다.
- `scripts/dashboard.py`: UI 입력 검증·포함 날짜 변환·관측 메타데이터·Phase 5 재사용. 메타데이터는 고정 읽기 전용 쿼리이며 파일의 mtime·크기 기준으로 캐시한다.
- `scripts/charts.py`: 승인된 집계의 카드·표·Plotly. 모델을 호출하거나 차트 코드를 생성하지 않는다.
- `.streamlit/config.toml`: 로컬 주소·사용 통계 전송 비활성화·브라우저 상세 예외 숨김·밝은 테마.
- `tests/test_dashboard.py`, `test_charts.py`, `test_app.py`: API 없는 서비스·계산 표시·Streamlit AppTest 검증.

당초 합의된 Streamlit·Plotly를 이 Phase에서 추가했다. 별도 프론트엔드/API 서버보다 기존 Python 로직을 그대로 재사용할 수 있고, Plotly로 허용된 인터랙티브 차트만 만들 수 있다. 직접 의존성은 Streamlit 1.66.1·Plotly 7.1.0을 추가했으며 기존 27개 버전은 제약 파일로 유지했다. 하위 의존성 포함 총 53개를 버전·해시로 고정했다.

공식 근거: [Streamlit form](https://docs.streamlit.io/develop/api-reference/execution-flow/st.form), [AppTest](https://docs.streamlit.io/develop/api-reference/app-testing/st.testing.v1.apptest), [Plotly 표시](https://docs.streamlit.io/develop/api-reference/charts/st.plotly_chart), [Plotly 선 그래프](https://plotly.com/python/line-charts/). 실제 설치 버전의 함수 시그니처도 확인했다.

## 보안·호출 동작

API 키 입력란이나 임의 DB 경로·SQL 실행창은 제공하지 않는다. 키는 로컬 `.env`에서 부모 API 클라이언트의 인증에만 사용하고 세션 상태·모델 문맥·브라우저·로그에 출력하지 않는다. 세션에는 마지막 요청과 제한된 집계·SQL·사용량만 유지하며 디스크에 자동 저장하지 않는다. 원본·리뷰·조회 결과는 모델에 보내지 않는다.

Phase 5의 AST·KPI 구조 검사·읽기 전용 별도 프로세스·시간/메모리/행 제한을 그대로 사용한다. 실패한 요청 뒤에 과거 성공 표를 새 결과처럼 남기지 않는다. API 사용량이 제공되지 않으면 “미제공”, 기준 분석처럼 요청이 없으면 “미사용”으로 표시한다. 금전 비용이나 잔여 크레딧은 추정하지 않는다.

캐시는 관측 메타데이터에만 적용한다. API 응답·키·클라이언트는 캐시하지 않는다. 초기 렌더링의 고정 DB 메타데이터 조회와 분석 후보 조회 횟수는 구분한다. 자동 SDK 재시도는 0이다.

## 검증과 남은 범위

- Phase 5 마지막 검토: 기존 187개 재검증·기존 CI 성공·실제 DB 4개 지표 기준 일치·DB 지문 보존을 확인했다. 진행을 막는 문제는 발견되지 않았다.
- UI 신규 32개와 기존 187개, 전체 219개 통과. 컴파일·53개 의존성 일관성도 통과했다.
- AppTest로 초기 렌더링 0회 실행, 4개 기준 분석, 재실행/모드 변경 중복 호출 방지, 데이터 부재·잘못된 날짜·차단/실패/확인 요청·미지원/한도 종료, 부분 합계 카드 숨김, 미제공 사용량·오류 정보 비노출을 검증했다.
- 실제 Chrome에서 4개 기준 분석의 카드·차트, 2024년 데이터 부재, 역전 기간 오류를 확인했다. 390×844 화면에서도 금액이 잘리지 않는 것을 확인했다.
- 브라우저 AI 질문 1개 성공: 2017년 상품금액 5,962,902.01(원본 단위)·주문 43,428건. 모델/API 1회·수정 0회·후보 조회 1회, 입력 1,923·출력 335·총 2,258토큰, 모델 약 4.33초·조회 약 0.85초. 별도 로컬 기준 SQL로 같은 기간 합계를 대조했다.
- 화면·DOM·메타데이터 근거는 `output/playwright/`에 로컬 보관하고 Git에서 제외한다. 실제 수치·명령·초기 화면 문제 수정은 [TEST_EVIDENCE](TEST_EVIDENCE.md)에 기록했다.
- 실제 AI 검증은 월별 질문 1개다. 다른 실제 모델 지표·다양한 표현·실제 계정 한도 오류 유발·다중 사용자·공개 배포·전체 접근성 인증은 검증하지 않았다. 데이터·SQL 범위는 기존 4개 KPI와 기간 변경으로 유지한다.
