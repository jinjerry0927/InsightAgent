## Phase 1 조사에 따른 구현 제안

아래는 관찰에서 도출한 제안이며 해당 구현 Phase에서 세부 설계를 검토한다.

- Vanna의 도구 입력 JSON 스키마와 DB 테이블 스키마를 구분한다. 자체 서비스에는 검증된 테이블·타입·키·실제 날짜 범위·승인 KPI를 명시적으로 전달한다.
- Vanna의 도구 그룹 접근 검사만 재현해 SQL이 안전하다고 판단하지 않는다. 별도 SQL 검사와 실행 환경의 제한을 결합한다.
- LLM에게 전달할 내용과 화면 표시 결과를 분리한다. 로컬 화면에는 실제 결과를 표시하면서 모델 전송량을 제한한다.
- Vanna의 반복 라운드 제한과 별개로, 자체 서비스는 LLM 호출·SQL 수정·DB 실행 횟수를 각각 센다.
- 승인된 기준 SQL을 소수의 예시로 제공한다. MVP에서 벡터 검색·성공 패턴 자동 저장을 도입하지 않는다.
- 시각화는 검증된 Python 코드와 허용된 차트 유형으로 생성한다.
