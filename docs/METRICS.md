# KPI 정의 — Phase 3 승인 기준

작성일: 2026-10-24. 사용자의 "Phase 3 시작하자" 요청을 직전 제안의 KPI 기준·Phase 3 착수 승인으로 반영했다. 아래 MVP 정의는 기준 SQL·테스트로 구현했고 실제 결과는 [BASELINE_RESULTS.md](BASELINE_RESULTS.md)에 기록한다. 재구매율은 후속 범위 정의로 남긴다.

## 공통 규칙

- 기본 분석 대상: `orders.order_status = 'delivered'`인 주문. 상태가 delivered인 배송일 NULL 주문도 상품 거래액·주문수에는 포함한다.
- 기간 기준: `order_purchase_timestamp`. 시작 시각 포함·종료 시각 제외인 `[start, end)`를 사용한다.
- 월: 원본 시각의 달력 월. 원본 시간대는 지정되지 않았으므로 임의 시간대 변환을 하지 않는다.
- 금액: 원본 금액 단위, 환율 변환 없음. 금액은 DECIMAL로 계산한다.
- 취소·unavailable·기타 진행 중 상태는 기본 KPI에서 제외하고 제외 기준·건수를 별도 표시한다.
- 구매 기간 전체와 delivered 주문의 기간은 다르다. 요청 기간에 관측 행이 없으면 "해당 조건의 데이터 없음"으로 응답하며 수치를 만들어 채우지 않는다.
- 부분 기간·경계 달과 원본 결측은 결과에 표시한다. 결측값을 0이나 배송 완료로 바꾸지 않는다.

## 1. 상품 거래액과 월별 매출 추이

- 사용자 표시명: **매출(배송 완료 상품금액·배송비 제외)**.
- 계산 단위: 주문 상품 행.
- 계산: 기간·상태를 충족하는 주문에 속한 `order_items.price`의 합.
- 배송비 `freight_value`, 결제금액 `payment_value`는 합산하지 않는다.
- 월 기준은 배송일이 아닌 구매일이다.
- 상품을 먼저 주문 단위로 합산하고 주문 테이블과 연결한다. 결제·리뷰는 이 계산에 직접 연결하지 않는다.
- 실제 회계 매출·순매출·환불 차감액을 의미한다고 표현하지 않는다.
- 상품 행 또는 가격이 누락되면 전체 상품금액을 NULL로 두고, 확인된 소계와 누락 건수를 별도로 표시한다. 원본의 실제 0원과 관측 부재를 구분한다.

대안: 배송비 포함 상품금액 또는 결제금액 합계를 사용할 수 있으나 의미가 달라진다. 첫 MVP는 위 정의를 추천한다.

## 2. 주문수

- 공통 기간·상태 필터를 적용한 `COUNT(DISTINCT order_id)`.
- 상품·결제·리뷰 연결 이후 행 수를 주문수로 사용하지 않는다.
- 상품 거래액과 비교할 때 동일한 주문 기간·상태를 적용한다. 상품이 없는 주문의 포함 여부와 건수를 별도 확인한다.

## 3. 상품 카테고리별 거래액 TOP 5

- 1번과 같은 기간·상태·금액 기준을 사용한다.
- 상품 행에 `products`와 카테고리 번역을 LEFT JOIN한다.
- 영어 번역이 없으면 원문 카테고리 코드를 유지한다. 원문 자체가 NULL이면 "미분류"로 표시한다.
- 전체 카테고리 합계가 1번 상품 거래액과 일치해야 한다.
- 정렬: 거래액 내림차순, 동률이면 카테고리 코드 오름차순. 정확히 최대 5개를 반환한다.

## 4. 배송 지연 건수·비율

- 모집단: delivered 주문 중 고객 배송일과 예상 배송일이 모두 있는 주문.
- 실제 지연 판단: `CAST(order_delivered_customer_date AS DATE) > CAST(order_estimated_delivery_date AS DATE)`.
- 같은 예정일에 도착하면 시각이 자정보다 늦어도 정상 배송으로 본다. 승인된 날짜 단위 해석이다.
- 분자: 위 조건을 만족하는 지연 주문수.
- 분모: 기간 필터 후 모집단 주문수. 분모가 0이면 비율은 NULL이며 데이터 부재를 알린다.
- 구매 월별로 구분한다. 배송 월별 추이는 별도 지표로 구분한다.
- delivered지만 고객 배송일이 없는 주문은 분모에서 제외하고 제외 건수를 표시한다. canceled인데 배송일이 있어도 모집단에 포함하지 않는다.
- 미배송 주문을 현재 날짜 기준 지연으로 판단하지 않는다. 이 데이터는 과거 스냅샷이다.

## 5. 평점과 배송 지연 관계

- 모집단: 4번 배송 비교 가능 주문 중 사용할 수 있는 평점이 있는 주문.
- 한 주문의 리뷰가 여러 개면 `review_answer_timestamp` 최신 → `review_creation_date` 최신 → `review_id` 오름차순으로 1개를 선택한다. 각 정렬에서 NULL은 마지막이다.
- 최신 리뷰를 대표 의견으로 본다는 분석 선택이며 원본의 보장된 의미는 아니다. 단순 평균으로 모든 리뷰를 쓰는 대안은 다중 리뷰 주문의 가중치가 커진다.
- 지연·정상 그룹의 주문수와 평균 평점을 비교한다. 그룹별 표본 크기와 결측 제외 건수를 함께 표시한다.
- 관찰된 관련성만 설명한다. 배송 지연이 평점 저하의 원인이라고 단정하지 않는다.
- 최신 리뷰를 먼저 선택한 뒤 평점 1~5의 유효성을 검사한다. 최신 평점이 없거나 범위 밖이면 과거 점수로 채우지 않고 제외 건수를 표시한다.
- 선택한 구매 기간 뒤에 작성된 리뷰도 원본 스냅샷에 있으면 대표로 선택될 수 있다. 기간 끝 당시의 의견을 재구성하는 분석은 아니다.

## 6. 재구매율 — 후속 범위 정의안

- 고객 식별자: `customer_unique_id`.
- 분모: 선택한 구매 기간에 delivered 주문이 1회 이상 있는 고유 고객수.
- 분자: 같은 기간에 delivered 주문이 2회 이상인 고유 고객수.
- 주문 상품 수가 아닌 고유 주문수로 판정한다. 분모 0이면 NULL이다.
- 관측 기간 안의 재구매율이며 고객 생애 전체 재구매율이 아니다. MVP 필수 구현에서는 제외한다.

## 승인과 Phase 3 구현·검증

상품금액·배송비·주문 상태, 구매일 기준, 날짜 단위 지연 판정, 주문별 대표 리뷰 선택은 사용자 진행 요청으로 승인되었다. [DECISIONS.md](DECISIONS.md)에 반영했다. 결측값을 0으로 채우지 않는 원칙과 대표 리뷰 선택을 실행 가능한 형태로 명확히 기록했다.

기준 파일은 `sql/monthly_sales.sql`, `sql/category_sales.sql`, `sql/delivery_delays.sql`, `sql/review_delay.sql`, `tests/test_metrics.py`다. 승인된 KPI를 AI 없이 실행하고 합성 기대값과 원본 CSV 독립 계산으로 검증했다.

- SQL은 `$start_at`, `$end_at`을 바인딩한다. category_sales의 `$top_n`은 기본 5이며, 내부 전체 카테고리 합계 대조에는 NULL 제한을 사용한다.
- delivery_delays는 구매 월별 결과이며 late_rate는 0~1 비율이다. 전체 기간 비율은 월별 분자·분모 합으로 계산하며 월별 비율의 단순 평균을 쓰지 않는다.
- category_code를 유지해 같은 번역명을 갖는 서로 다른 카테고리를 합치지 않는다. 동률에서 NULL 코드는 마지막이다.
- 기간·상태에 맞는 관측이 없으면 no_data와 빈 결과를 반환한다. 관측된 0원 주문은 정상 데이터로 유지한다.
- 신규 지표 테스트 23개, 기존 적재 테스트를 포함한 전체 34개가 로컬에서 통과했다. 원격 검증 기록은 해당 Phase 3 PR의 Checks를 따른다.
